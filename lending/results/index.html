LENDING / API REFERENCE

Retrieve loan results

GETUse the full results_url returned in the application response

After an accepted application, the gateway may return a results_url. This URL points back to Authorised Compliance and contains an opaque, short-lived token.

Returned results URL

Read the full HTTPS results_url from the application response. It points to the AC API and includes the token needed to retrieve results. Treat the URL as an opaque value: do not construct, modify or substitute its path or query parameters.

How to poll

  1. Read results_url from the initial XML response, if present.
  2. Send GET to that exact URL over HTTPS.
  3. Include the same X-AC-Client-ID and x-api-key values used for submission.
  4. Read the returned XML response.
  5. If <offer_results><awaiting_response> is greater than 0, further responses may be pending. Retry only according to your agreed polling policy.
  6. Stop when all responses have arrived or the available polling window has elapsed. Avoid aggressive or unlimited polling.

For example, after extracting the full returned URL into RESULTS_URL:

curl --request GET "$RESULTS_URL" \
  --header "X-AC-Client-ID: YOUR_CLIENT_ID" \
  --header "x-api-key: YOUR_API_KEY"

Example polling result

<response>
  <result>20</result>
  <reference>EXAMPLE_REFERENCE</reference>
  <offer_results>
    <accepted>1</accepted>
    <rejected>3</rejected>
    <awaiting_response>0</awaiting_response>
  </offer_results>
  <offers>
    <!-- Offer details, including lender and redirect information, if available -->
  </offers>
</response>

Token security

  • Tokens are bound to the submitting AC client; another client's API key must not grant access.
  • Results tokens have a limited lifetime. Retrieve results promptly and do not treat the token as a permanent application identifier.
  • Expired, modified or malformed tokens are rejected.
  • A results token is not a long-term archive or application history lookup key.

One-step versus two-step responses

Some campaigns may return final offers directly in the submission response, without a results URL. An integration must support both cases. Poll only if AC actually returns a results_url. An initial XML result with offers must be processed without inventing a polling link.

Polling interval and rate limits

Do not assume a specific approved polling interval from this document. Lender responses may take time. Follow the polling interval and request limits agreed with AC. Handle 429 with bounded exponential backoff, honoring Retry-After if supplied.
